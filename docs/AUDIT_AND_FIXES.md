## 4. Kit contract (verified 2026-09-07 at developers.kit.com)

| Step | Endpoint | Documented behaviour used |
|---|---|---|
| auth | header `X-Kit-Api-Key` | API-key limit 120 requests / rolling 60 s |
| lookup | `GET /v4/subscribers?email_address=…&status=all` | exact-match filter; `state` ∈ active, inactive, cancelled, bounced, complained |
| create | `POST /v4/subscribers {email_address}` | upsert: 201 new, 200 existing; state changes are **not** supported by this endpoint |
| form | `POST /v4/forms/{id}/subscribers {email_address, referrer}` | subscriber must exist; 201 added, 200 already; `referrer` utm values are stored as `referrer_utm_parameters` |
| tag | `POST /v4/tags/{id}/subscribers {email_address}` | 201 applied, 200 already |
| errors | 401 / 422 / 429 / 500 | mapped to a generic 503 `provider_unavailable` with `Retry-After`; provider text never reaches the browser |

Not documented, therefore treated as unknown and covered by the live test in the runbook: whether the form endpoint triggers the form's confirmation (incentive) e-mail for API-added subscribers, and whether re-adding re-sends it.
