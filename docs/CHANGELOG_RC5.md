## Signup timeout (RC3 review §2) — `build/site.js`
- The 12 s deadline now covers the whole request including `res.json()`. One attempt token per submission; the timer itself restores the form (label, `disabled`, `readOnly`, `aria-busy`, `is-busy`), announces the timeout message, focuses the input, then aborts the fetch. `AbortError` is preserved (a body-read failure becomes `{}` only when it is not an abort). Any later resolution or rejection for a timed-out or superseded attempt is ignored, so a late 200 can never flip the form to success or disturb the next attempt. Duplicate-submit guard, honeypot, seven placements, interest capture and the "valid successful response required" rule are unchanged.
- Regressions in `tests/run_tests.py` (browser, real timers, through the local static server + streamed proxy + raw-socket stub): headers-then-stalled-body → restored in 12.2 s; no headers → 12.1 s; late 200 at 14 s ignored; retry after timeout succeeds; existing 500/429/malformed/200-without-ok/network/triple-submit cases kept.

## Privacy copy and interest logging (RC3 review §3) — `build/legal/privacy.html`, `build/build.py`, `server/subscribe-core.mjs`
- Policy: campaign values are kept in browser session storage and sent with the signup; they are recorded in operational signup logs, not in the Kit record (stated in "What we collect", "Email service provider" and "Analytics and cookies"). Kit stores email and signup source; the selected product interest reaches Kit **only where the list is configured with a matching tag or field**, otherwise it stays in the logs. No retention period invented; no tracking added; no V4 attribution on the V3 path.
- `interest_recorded` now means what it says. `tagIdFor(env, interest)` maps each of the six interests (`newsletter, show, index, benchmark, benchmark-calculator, benchmark-report`) to its own `KIT_TAG_*` variable only; non-numeric values are ignored and never break a signup. `interestCapture()` reports `{recorded, via}`: `newsletter` = accepted form membership (`via:form`); a product interest = its own tag on the accepted call (`via:tag`) or the configured `KIT_V3_INTEREST_FIELD` (`via:field`); otherwise `false/none` with a note naming the missing variable. A generic newsletter tag or the generic Benchmark tag never counts for calculator/report. Suppressed, failed and disabled requests report no recorded interest. V4 path: `recorded` only when the interest's own tag call actually succeeded. Public responses unchanged and uniform; logs still carry only the keyed hash.
- Tests: `tests/core_unit_test.mjs` (new, dependency-injected, 31 checks: absent mappings for all five product interests, newsletter-only tag with a product request, generic Benchmark tag vs calculator/report, matching tags, invalid values, interest field, newsletter interest, suppressed and failed requests, disable switch, log hygiene) plus new live-mock checks in `run_tests.py`.
