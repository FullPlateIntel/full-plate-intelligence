## 8. Rollback and emergency stop

- **Rollback**: Netlify keeps every deploy. Deploys → select the last known-good deploy → "Publish deploy". Static pages and the function roll back together; environment variables are unaffected. Record which deploy is the known-good one before promoting RC5.
- **Emergency stop for signups (active V3 provider)**: set `SIGNUPS_DISABLED=1` in Netlify environment variables (Functions scope), then **trigger a new deploy** (Deploys → Trigger deploy → Deploy site) or re-publish the current deploy — Netlify applies environment changes only to new deploys. Result: every submission shows the visible "temporarily unavailable" message (JSON 503 `disabled`) and no-JavaScript posts land on `/subscribe/error/`; nothing is written to Kit and nothing is silently accepted. To resume, clear the variable and deploy again. Unsetting `KIT_API_KEY` does **not** stop signups — that is the optional V4 credential; the V3 workflow uses `KIT_V3_API_KEY` + `KIT_FORM_ID` (clearing those also stops signups, with the 503 `not_configured` response, but the switch is the documented procedure).
- Content rollback to the single-file version is possible (ORIGINAL file) but loses routing/SEO; prefer publishing the previous deploy.
